    @sovereignbase/sequencer

    Sequencer

    Sequencer provides a deterministic total ordering for distributed data. It allows independently operating actors to make concurrent changes and eventually converge on the same state without relying on network arrival order or perfectly synchronized clocks.

    Usage

    Simple typed API

    import { Projection } from '@sovereignbase/sequencer'

    const projection = new Projection<string>(1)

    const gossip0 = projection.insert(['Hello World'], 0)
    console.log(projection.value(0)) // "Hello World"
    const gossip1 = projection.replace(['Hello Dude'], 0, 0)
    console.log(projection.value(0)) // "Hello Dude"
    const gossip2 = projection.remove(0, 0)
    console.log(projection.value(0)) // undefined

    projection.destroy()

    See documentation

    Register active Actors, including offline Actors, before removals. When every active Actor acknowledges the same complete removal Session frontier, sequence() omits its masks and deleted Footage. Actor membership remains. See the compaction contract.

    Errors

    Library-reported failures throw SequencerError, with a stable SequencerErrorCode and a message prefixed with {@sovereignbase/sequencer}. Both are exported from the package. The constructor accepts standard ErrorOptions, including cause.

    Code Meaning
    PROJECTION_DESTROYED An operation was called after the Projection was destroyed.
    NATIVE_OPERATION_FAILED The native runtime reported an initialization or operation failure.

    Invalid Gossip or Sequence input to apply() or merge() returns undefined. Platform errors retain their original types.

    Tested realtime and offline text editing behaviour examples

    • Online and offline editors: six editors converge through delayed, reversed and shuffled delivery, including offline changes arriving during online editing.
    • Concurrent replacements: independent replacement histories retain the same surviving content across delivery orders.
    • Restart and redelivery: stored Sequences preserve visible content through hydration, duplicate delivery and further edits.
    • Peer-to-peer fanout: independently editing browser peers synchronize through BroadcastChannel.
    • WebSocket fanout: three browser peers converge through a stateless JSON Gossip relay.
